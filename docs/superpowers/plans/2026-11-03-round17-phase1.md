# Round 17 Phase 1 (round 16 money features demo-proof, spouse) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Round 17 points 1–7:
- birthday charges go on the next monthly invoice (no separate birthday invoice);
- pick-up shown to the family, Plans preview fixed;
- field trip fixes (i18n label, re-price, delete, family sees the fee);
- an "On your next bill" preview;
- proof of payment shown on the invoice and checked by the server;
- a visible Make billing contact button and an Emails list;
- the spouse in the Family tab.

**Architecture:**
- Everything that lands on next month's invoice is a `PendingCharge`. `runLinesFor` (`rules/billing.ts:158-160`) already bills un-invoiced ones; `issueRun` (`actions/finance.ts:104-109`) marks them; `invoice.void` (`finance.ts:229`) releases them.
- A pending charge gets an i18n label (key + params) and a `source` that links it to the outing or the celebration it came from, so those can re-price or remove their own charges.
- Pure rules in `packages/shared/src/rules`, immer actions in `actions`, as in rounds 12–16.

**Tech Stack:** TypeScript, immer actions, zod (some actions), React 18, vitest, Playwright; pnpm monorepo; Hono + Drizzle server.

**Spec:** `docs/superpowers/specs/2026-11-03-round17-design.md` §Phase 1 (points 1–7), Conventions and Testing. KC approved the spec on 3 Nov.

- Labels: "Birthday · {item}" / "Ulang tahun · {item}"; "Field trip · {title} · {date}" / "Karyawisata · {title} · {date}".

## Rulings made while writing this plan

- **R1 Label keys** live in the `inv` namespace beside the other line labels (`i18n/en/core.ts:122-124`, `id/core.ts:118-120`): `inv.line.birthday` = `'Birthday · {item}'` / `'Ulang tahun · {item}'`, `inv.line.fieldTrip` = `'Field trip · {title} · {date}'` / `'Karyawisata · {title} · {date}'`. `date` is an ISO date param, which `useT` already localises. `translate` falls back to the raw string, so old free-text labels (tests, `'Outing lunch'`) still render.
- **R2 `PendingCharge` gains** `params?: Record<string, string | number>` and `source?: { type: 'event' | 'celebration'; id: string }`. `runLinesFor` copies `params` onto the line.
- **R3 Pending charge ids:** a birthday charge is `cel-<celebrationChargeId>`; a field trip charge stays `trip-<eventId>-<memberId>`.
- **R4 `CelebrationCharge.invoiceId` goes;** "invoiced" is read from the pending charge (`d.pendingCharges['cel-' + x.id]?.invoiceId`). Helper `celebrationChargeInvoice(s, charge)`.
- **R5 Declining or cancelling a celebration** removes its un-invoiced pending charges (they would otherwise bill for a party that did not happen). Invoiced ones stay.
- **R6 Field trip fee edits after the date:** `calendarEvent.update` with a patch that changes only `fee` is allowed after the date while the outing has an un-invoiced charge. Any other past edit keeps `cal.err.pastEvent`. `calendarEvent.delete` keeps its past check; on a live delete it removes the outing's un-invoiced charges.
- **R7 Family projection:** families get their own members' un-invoiced pending charges, and `wentIds` filtered to their own members (today every family receives every family's ids: `project.ts:82`).
- **R8 Next bill** = un-invoiced pending charges + the pick-up fee for next month when on. It is a preview: the plan fee is left out (the family knows it; leave and stops would make a wrong number).
- **R9 Proof check is server-side only** (`apps/server/src/app.ts` before `runAction`): ClubState has no media collection, so the shared action keeps its format check (`mediaIdOf`). New `mediaExists(clubId, id)` in `apps/server/src/media.ts`; refusal code `finance.err.proofMissing`, status 422.
- **R10 Emails list** is on the Documents tab as the spec says. Finance does not see Documents (`MemberProfile.tsx:50-56`); finance sees the "Emailed to" line on each invoice. Recorded for KC.
- **R11 Make billing contact** asks first ("Unpaid invoices move to {name}"), then runs `family.setPrimary { memberId, familyId }` (roles already lobby, finance, mgmt). The MemberDialog toggle stays.
- **R12 Spouse edits** use `members.updateDetails { memberId, patch: { spouseId } }` (front desk and management; a lobby edit goes to review as today).

## Review Focus

1. **A cancelled or declined birthday with charges:** the charges must not reach the invoice. *Test: Task 2.*
2. **Removing a birthday charge after the run:** refused with `err.charged`; after the invoice is voided it can be removed. *Test: Task 2.*
3. **Re-pricing a field trip after some charges are invoiced:** only the un-invoiced ones change. *Test: Task 3.*
4. **A family seeing other families' trip attendance:** `wentIds` carries only their own members. *Test: Task 1.*
5. **A forged proof id** (right format, never uploaded) is refused by the server. *Test: Task 5.*

**Goal:** KC's eight round 18 points:
1. an Owner quick-login account;
2. the Roles page sectioned like Tasks, in two columns on wide screens;

4. findable field trips;

**Architecture:**

- The web screens consume them: Settings, Roles, Calendar, search, and the proof viewer.
- The seed and e2e come last.
- Tasks are grouped into three tracks that touch different files, so they can run in parallel worktrees, then merge before the seed task.

**Tech Stack:** pnpm monorepo, TypeScript, React 18 (data router), Hono + Drizzle + Postgres (port 5434), Vitest, Playwright.

**Spec:** `docs/superpowers/specs/2026-11-03-round18-design.md`

## Global Constraints

- Shared immer actions live in `packages/shared/src/actions` (`defineAction`) and pure rules in `packages/shared/src/rules`. Role checks run server-side via `can` and `permit()`.
- The UI is dense and phone-first, with 44 px targets, ink/grey/white on the warm staff skin. No pastel tints, no descriptive filler text. Phones use iOS grouped lists.
- Every string exists in EN and ID. The ID objects are typed `Same<typeof EN.x>`, so a missing key fails typecheck.
- The seed stays RNG-neutral (no new random draws before existing ones). `CP_SEED_SMALL=1` keeps working with exactly its 5 members (m1, m2, m10, m20, m46). Club state stays under 7,500,000 characters at the real date and at 2026-12-30 (`seed/history.test.ts`).
- The API dev port is 8788; never use 8787.
- Tests stay minimal: typecheck, unit tests for new rules and actions, one e2e spec on phone, and screenshots at phone, tablet and laptop.
- With no notice settings stored, behaviour is exactly as today: every kind is 14 days, and December's deadline is 17 Nov.
- Few-visits default: `daysBeforeMonth` 16. December has its alert on 15 Nov and closes 17 Nov. November has its alert on 16 Oct and closes 18 Oct.
- Field trip labels: EN "Field trip", ID "Karyawisata". The data kind stays `'outing'`.
- New contact: Ratna Rahayu, login `ratna` / `citra123`, daughter of Oma Sri Rahayu. Full roster only.

## Rulings (made while planning; easy to reverse)

- **R1** `club.updateSettings` takes `notice?: Partial<{ downgrade; stop; leave }>` and no longer takes `noticeDays`. Settings is its only web caller. Stored `noticeDays` stays as the fallback for clubs without `notice`.
- **R2** The few-visits list closes at the **stop** deadline. `fewVisitsAlertDay` uses `max(daysBeforeMonth, stopDays)`, so a later notice change can't put the alert after the close (validation on save plus this clamp).
- **R3** The data for the "last changed" line on the Roles page already exists (`ClubSettings.accessChanged`). Roles reuses the Tasks parts by moving `RoleRow`, `RoleHead`, `ScoreBar`, `RoleIcon` and `Lines` into `apps/web/src/components/roleparts.tsx`. Tasks then imports them from there, with no visual change to Tasks.
- **R4** `proofKind` is sent by the client (from the picked file's type). The server doesn't sniff it. Old payments use `HEAD /api/media/:id` once on open, and the result is cached in memory.
- **R5** Search indexes calendar events from 3 months back to 6 months ahead, all kinds, by title. Field trips also match "field trip / trip / karyawisata". Roles that can't open Calendar get no event results.
- **R6** Oma Sri's member id is `m_sri` and Ratna's contact id is `f_ratna`. They are seeded in a new `seed/r7/round18.ts`, after round 17, and skipped when `CP_SEED_SMALL=1`.

# Round 15 Phase 1 (day-to-day fixes) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The twelve day-to-day fixes from KC's round 15 list:
- check-out times;
- past family sessions done;
- phone search button;
- Check on "Not seen for";
- enquiry "Other" source;
- the nanny on rows and among the family, with family photos;
- plan filter;
- compact lunch photos;
- dementia wording;
- the closed-days year summary and month marker;
- Next month's member list.

**Architecture:** Mostly web changes in apps/web, with small shared additions (a rule or a field) in packages/shared where data changes. Each task is a self-contained slice with its own tests. Phase 2 (programme review in the Calendar, the plan catalogue, sign at registration, directory categories, dish photos) has its own plan.

**Tech Stack:** TypeScript, React 18, immer actions, vitest, Playwright; pnpm monorepo.

**Spec:** `docs/superpowers/specs/2026-10-27-round15-design.md` §Phase 1 (points 1–12) and its Conventions and Testing sections. KC confirmed all five spec assumptions on 27 Oct.

## Global Constraints

- **Conventions:**
  - shared immer actions in `packages/shared/src/actions`, pure rules in `rules`;
  - role checks server-side through `can`;
  - dense phone-first UI, 44 px targets, ink, grey and white with the warm staff skin, no pastel tints;
  - every string in EN and ID;
  - family edits go through approvals.
- **Seed:** RNG-neutral, `CP_SEED_SMALL=1` working, club state under the 7,500,000-character cap at the real date and at 2026-12-30 (headroom about 52,000).
- **Tests:** typecheck, unit tests for new rules and actions, one e2e pass for the phase.
- Run vitest from the repo root (only the root config gives the web project jsdom).
- Run e2e through `scripts/e2e-all.sh` with a private name and port, e.g. `E2E_NAME=e5 E2E_PORT=8891` (pinned CP_DEMO_DATE=2026-10-21, CP_SEED_SMALL=1).
- **Disk:** the disk is nearly full; free space before a full e2e run if `ENOSPC` appears.
- **Point 8:** until phase 2's catalogue, the plans are Flex and Gold. Anything that lists plans must read them from one shared helper (Task 8), so phase 2 only has to extend that helper.

## Rulings made while writing this plan

- **R1 Check on choice:** the "Not seen for" choice applies on that device to the Check on sheet, the lobby rail's Check on count, and the Members "Check on" filter. One web hook reads it.
- **R2 Search button column:** the phone search button sits in the rightmost column of the floating stack, one button above the top button there:
  - above the camera for roles with the quick camera;
  - above Tasks for roles without one;
  - at the stack's bottom position for a role with neither.
- **R3 Source "Other":** the "Where from?" answer is optional, at most 80 characters. Changing the source away from Other clears it.
- **R4 Closed-days list:** it shows the same items in the staff and family Year views. Outings are included and labelled "Outing", since the club is away that day.
- **R5 Next month list:** it is a new first tab "Members", before Changes and Unpaid. It covers members who are active on the 1st of next month, plus those whose recorded change stops them.

## Review Focus

1. **No check-out:** a visit with no check-out (still in, or forgot to check out) shows "In 09:58" only, never a blank "Out". The departure averages and chart skip it. *Tests: Task 1.*
2. **Storage blocked:** the stored "Not seen for" value is missing or `localStorage` throws, so the list falls back to Automatic. *Test: Task 4.*
3. **Source changed back:** an enquiry switched from Other to Instagram loses its "Where from?" text. *Test: Task 5.*
4. **Closures crossing a boundary:** a closure that spans months or the year boundary (30 Dec–2 Jan) is listed once per year, clipped to that year, with the right day count. *Test: Task 10.*
5. **Next month edge cases:**
  - a member who stops this month, or is already on leave, or a new member starting next month, gets the right label;
  - a member who stops is never shown as "Continues".
  *Test: Task 11.*
